# AI Guidelines for 3D Printables Repository

You are helping to manage an open source repository of 3D printable models. This repository contains FreeCAD files (*.FCStd), OpenScad files (*.scad), preview images, and photographs.

## Key Repository Structure
- Root directory: Contains subdirectories with 3D models
- `./images/` directory: Contains only real photographs (not renders)
- Preview files: Usually named `*-preview.png` and located alongside FreeCad (`*.FCStd`) and OpenScad(`*.scad`) files.

## Protocol

### Extract All Previews
When user requests to extract all previews, ONLY extract previews without modifying README.md:

- Use `extract_all_previews` function to extract all available previews

### Extract Specific Preview
When user requests to extract specific preview, ONLY extract this one single preview without modifying README.md:

- Use `extract_one_preview` function for one or more specific files
- Example: "extract preview for keychain.FCStd"

### Sync
When user requests to sync images, follow these steps in order:

1. **Build directory tree**: Use `directory_tree` to find all `*.FStd` and `*.scad` files in the project.
2. **Check file timestamps**: Use `get_file_info` to get timestamps of those FStd which have previews and for their previews respectively (do not check file info if FCStd does not have preview, consider it outdated). 
3. **Extract Previews** Extract previews only for FCStd and scad files modified after their existing preview files:
    - Use `extract_one_preview` to extract outdated previews from FStd models (use `extract_all_previews` if large number of previews is outdated)
    - Use `extract_one_openscad_preview` to extract outdated previews
4. **Find preview files**: Use `directory_tree` to find all `*-preview.png` files matching `*.FCStd` and `*.scad` files (typically `*-preview.png` format).
5. **Update README**: Add missing preview images to README.md, but skip any models which already use corresponding photographs from `./images/`.
    - **Make sure to preserve photographs**: Files in `./images/` are real photographs - never replace them with rendered previews.
    - **Don't add duplicates**: Don't add `*.FCStd` file if it is already referenced in the README, only update preview if photograph is not used.
6. **Reference correctly**: Link directly to preview files in subdirectories, do NOT copy them to `./images/`.

### Arbitrary commands
Do you best to execute other user's commands.

## Readme format

Insert every folder as a level 2 header, for example `bells-and-whistles` directory becomes `## Bells and Whistle` header.

Table example:

| Preview | Description |
|---------|-------------|
| ![Bell](images/bell-photo.png)<br/>**[bell.FCStd](bells-and-whistles/bell.FCStd)** / [bell.3mf](bells-and-whistles/bell.3mf), [bell-decorated.3mf](bells-and-whistles/bell-decorated.FCStd) | Bell |

First row should include preview or photo followed by a link to the model itself, followed by links to 3MF files which you can attribute to this model.

## Important Rules
- ✅ Photographs go in `./images/` directory
- ✅ Rendered previews stay with their `.FCStd` files
- ❌ Never copy preview renders to `./images/`
- ❌ Never replace photographs with renders
- ❌ Do not use `read_file` on `.FCStd`, this is a binary format.
